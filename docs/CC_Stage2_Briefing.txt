2.2 identity.py — The Entire API Surface
Create cc/identity.py. It must expose exactly these three functions and nothing else that is public:

import nacl.signing
import base64, json, os, stat

KEY_FILE = 'cc_identity.key'
PUB_FILE = 'cc_identity.pub'

def generate_keypair() -> tuple[str, str]:
    """Returns (sk_b64, vk_b64). Writes both files."""
    sk = nacl.signing.SigningKey.generate()
    vk = sk.verify_key
    sk_b64 = base64.b64encode(bytes(sk)).decode()
    vk_b64 = base64.b64encode(bytes(vk)).decode()
    with open(KEY_FILE, 'w') as f:
        json.dump({'sk': sk_b64, 'vk': vk_b64}, f)
    os.chmod(KEY_FILE, stat.S_IRUSR | stat.S_IWUSR)  # 600
    with open(PUB_FILE, 'w') as f:
        json.dump({'vk': vk_b64}, f)
    return sk_b64, vk_b64

def sign_payload(payload_bytes: bytes) -> str:
    """Load key from file. Sign payload. Return base64 sig."""
    with open(KEY_FILE) as f:
        sk_b64 = json.load(f)['sk']
    sk = nacl.signing.SigningKey(base64.b64decode(sk_b64))
    sig = sk.sign(payload_bytes).signature
    return base64.b64encode(sig).decode()

def verify_payload(payload_bytes: bytes, sig_b64: str, vk_b64: str) -> None:
    """Raises nacl.exceptions.BadSignatureError if invalid."""
    vk = nacl.signing.VerifyKey(base64.b64decode(vk_b64))
    vk.verify(payload_bytes, base64.b64decode(sig_b64))

Notes for your self-review before committing:
    • KEY_FILE must be chmod 600. The os.chmod line is not optional.
    • sign_payload loads from disk every call — that is correct for now. No in-memory key caching in Stage 2.
    • verify_payload raises on failure. Callers catch it. Do not swallow the exception in this function.

3. Week 2 — Cross-Runtime Import
The proof: export a capsule on machine A. Import it on a different runtime (or fresh process). State hashes match. Signature verifies.

3.1 What to Add to capsule.py
capsule_import(path) must do these things in order. If any step fails, raise — do not continue.

    • Load the capsule JSON from path.
    • Verify the signature (Week 1.5 code). Reject if invalid.
    • Check prev_capsule_hash if present. If the capsule references a prior capsule hash and the local store has that hash, confirm continuity. If not found locally, log a warning — do not reject (first import has no history).
    • Check capsule_series_uuid. Store it. Two capsules with different series UUIDs are parallel branches — they must not be merged silently.
    • Detect unit conflicts: for each memory unit in the incoming capsule, check if a unit with the same id already exists locally with a different content_hash.
    • Resolve conflicts explicitly: no silent merges. The resolution must be one of keep_local or keep_incoming. In Week 2, the resolution is hardcoded to keep_local unless the caller passes override=True.
    • Write accepted units to memory. Return a structured import report.

4. Week 3 — Policy and TTL
The proof: a unit with a TTL expires. mem_find never returns it after expiry. TTL survives a capsule export/import boundary.

4.1 TTL Enforcement in memory.py
In mem_find: before returning any unit, check expires_at. If expires_at is not null and expires_at < utcnow(), do not return the unit. Do not delete it — mark it as expired in a status field. Expired units must still appear in the receipt chain so replay is not broken.

TTL field in the memory unit schema:
expires_at: str | None   # ISO8601 UTC, null means never expires

4.2 Canon Scope — Immutable After First Commit
In the Verifier phase of runtime.py: if a memory write targets scope='canon' and a unit with that id already exists with status='committed', reject the write. Return verdict=FAIL with reason='canon_immutable'. The staged write is discarded. No exception — a controlled FAIL receipt is correct.

4.3 Policy Rules in Verifier
Policy rules are evaluated in the VERIFY phase. They are plain Python callables, sandboxed by not being given access to the db or runtime state directly — they receive only the staged_payload dict and the policy_config dict.

def policy_summary_length(staged: dict, config: dict) -> tuple[bool, str]:
    max_len = config.get('summary_max', 240)
    summary = staged.get('summary', '')
    if len(summary) > max_len:
        return False, f'summary {len(summary)} chars exceeds max {max_len}'
    return True, 'ok'

Built-in policies to implement in Week 3: summary_max (default 240), bullets_max (default 5). No imports inside policy functions. If a policy function raises, it is treated as a FAIL.

5. Week 4 — Profile Layer
The proof: a named profile can be written and read. Profile writes go through the full PLAN→ACT→VERIFY→COMMIT cycle — no shortcut path. Persona drift is traceable via provenance.

5.1 Profile Schema
{
  "profile_id": "<uuid4>",
  "name": "core" | "style" | "work" | "canon",
  "fields": { ... },
  "created_at": "<ISO8601>",
  "updated_at": "<ISO8601>",
  "provenance": [
    { "receipt_id": "...", "field": "...", "old": "...", "new": "..." }
  ]
}

Provenance is append-only. Every field change records the prior value and the receipt_id that authorized the change. This is how persona drift becomes auditable without a separate audit log.

5.2 ZW Block Parser — Standalone
The ZW block parser (zw_block.py) must remain standalone — no EngAIn imports, no external dependencies beyond hashlib. It parses the header line, @meta lines, and section body. It produces a canonical dict that can be hashed. If parsing fails, it raises ParseError — not a silent empty return.

id: ch02
scope: canon

  - Guardianship fragile

6. Your Self-Testing Protocol
You have full editorial and self-testing authority. Here is how to use it without breaking things:

6.1 Before Writing Any Code

    • Write the test signatures first (empty bodies with docstrings).

6.2 After Writing Each New Function
    • Fill in the test body. Run it. It should fail (function is a stub).
    • Implement the function until the test passes.
    • Run the full suite. If an earlier test breaks, stop and fix it before continuing.

6.3 Editorial Authority Means
    • You may refactor any function signature that is in the file you are currently working on, as long as all tests still pass after the refactor.
    • You may add helper functions that have no public exposure and no tests — but they must be covered by the public function's test.
    • You may NOT change the state machine phases, the receipt schema, or the chain hashing algorithm. Those are frozen.
    • You may NOT add a dependency without recording it as a comment in the file where it would be used, marked TODO:DEPENDENCY, and bringing it to the human for approval.

6.4 When Something Breaks
Isolate before fixing. Run the single failing test with -v to see the exact assertion. Read the receipt log if state is involved. Do not guess — the receipt chain tells you exactly what happened and in what order. Use it.
